raw/, ce sont mes sources. Des articles clippés, des transcripts de calls, des exports Search Console, mes notes de journal.

Claude y lit, et il n'y écrit jamais. C'est la seule règle que je n'ai pas assouplie en cinq mois.

La raison tient en une phrase. Le jour où l'agent reformule une source pour la rendre plus claire, tu perds la trace de ce que l'auteur avait écrit. Tu ne peux plus le citer, et tu ne peux plus le vérifier.

Les 2 709 fichiers de raw/ ne sont pas tous du texte. raw/data/ porte 1 722 fichiers, presque tous des exports Search Console.

wiki/ est le domaine de Claude. Trois types de pages portent l'essentiel.

Une fiche source par document ingéré. Elle porte le contexte, les chiffres relevés, les limites de la source, et l'angle que j'ai demandé à creuser.

Une entité par objet nommé : un algo Google, un outil, un prospect, un moteur de réponse.

Les concepts portent les mécaniques. Le passage ranking, le grounding score, l'information gain : une page chacun, qui s'enrichit à chaque source qui en parle.

Les pages se citent entre elles avec des wikilinks, et ces liens forment le graphe qu'Obsidian affiche.

Le pattern wiki persistant optimise-t-il structurellement le Grounding Score ?

Contexte : question flaggée « à filer » depuis l'ingest de [[sources/2026-04-11-karpathy-llm-wiki]]. Après l'ingest de [[sources/2026-04-11-seo-ia-tim]] et de 6 newsletters, le matériau est suffisant pour répondre.

Réponse courte. Oui, mais de façon indirecte et non validée empiriquement. Le pattern produit par construction des pages qui satisfont les deux axes du [[concepts/grounding-score]] : proximité vectorielle et divergence informationnelle. Aucun test terrain ne le prouve encore.

Cinq mécanismes structurels : agrégation vectorielle progressive · surprise informationnelle maintenue · résistance au [[concepts/weight-decay]] · information gain par construction · structure Associative Memory Chain.

Le registre des hypothèses la cite. Cinq mois plus tard elle sert encore.

Ce qui change quand la base devient grosse

Karpathy annonce un seuil. Vers cent sources, index.md ne suffit plus à router vers les bonnes pages.

Chez moi le seuil est tombé le 7 août 2026, à 110 sources. L'outil était déjà là : j'avais ajouté une recherche vectorielle locale le 26 mai.

ChromaDB, embeddings paraphrase-multilingual-mpnet-base-v2, en local et gratuit. Un chunk par section H2. Le fichier de base pèse 231 Mo.

C'est là que le frontmatter paie. Chaque morceau de texte indexé garde les champs de son fichier d'origine, donc le filtre passe d'abord sur le type, le tag et le statut. La recherche sémantique ne travaille ensuite que sur ce qui reste.

filtrage déterministe avant la recherche cosinus
$ ./kb search "RRF" --type concept --tag aeo --k 8
$ ./kb rebuild          # audit frontmatter + concepts.json + index incrémental
$ ./kb audit-frontmatter # liste les fichiers raw/ sans frontmatter

index.md n'a pas disparu pour autant. Le wiki compile une fois, le moteur retrouve à chaque question.

Le graphe se mesure aussi. data-proprietaire est cité par 268 fichiers et pointe vers 34 pages.

Cette page-là non plus, je ne l'ai pas écrite.

Ce que tu dois mettre en place chez toi

Compte quinze minutes pour l'installation. Le premier ingest prend plus de temps que les suivants, parce que tu corriges ce que Claude a compris.

installation
$ npm install -g @anthropic-ai/claude-code
$ mkdir ma-base && cd ma-base
$ mkdir -p raw/articles raw/data raw/clients raw/notes
$ mkdir -p wiki/sources wiki/entities wiki/concepts wiki/queries
$ touch AGENTS.md wiki/index.md wiki/log.md
$ git init && git add . && git commit -m "bootstrap"
$ claude

Dans Obsidian, ouvre le dossier ma-base. Le bouton s'appelle « Open folder as vault ».

Obsidian est gratuit. Claude coûte environ 20 € par mois. Un SaaS SEO coûte plutôt 50 à 300 € par mois (relevé avril 2026).

Six sections suffisent dans AGENTS.md pour commencer : la mission, ta doctrine, l'arborescence, les types de pages, les conventions, les workflows.

AGENTS.md — le minimum qui tient debout
# AGENTS.md — ma base SEO

## Mission
Construire une base persistante qui sert mon travail de consultant SEO.

## Doctrine (non négociable)
- Pas de source = pas d'affirmation. Aucun chiffre inventé.
- Un volume manquant s'écrit « à sourcer », jamais un nombre plausible.
- Conversion avant visibilité. Mots-clés business d'abord.

## Architecture
raw/ est immuable. L'agent lit, il n'écrit jamais dedans.
Tout ce qu'il produit va dans wiki/.

## Types de pages
sources/ (une fiche par document) · entities/ (objets nommés)
concepts/ (mécaniques) · queries/ (mes questions filées)

## Conventions
- kebab-case strict, pas d'accents, un sujet = un fichier
- frontmatter obligatoire : type, title, tags, created, updated,
  sources, confidence, status
- wikilinks [[...]] uniquement, 2 liens sortants minimum par page

## Workflows
INGEST : lire en entier → me résumer et demander l'angle → créer la fiche
dans sources/ → mettre à jour entities et concepts cités → mettre à jour
index.md → append dans log.md → me rendre le compte rendu. Une source
à la fois.

QUERY : lire index.md → ouvrir 3 à 8 pages → répondre avec un wikilink
sur chaque affirmation → proposer de filer la réponse dans queries/.

LINT : liens cassés, pages orphelines, frontmatter absent, contradictions,
sources de plus de 12 mois. Rapport seulement, aucune réparation.

Tu le feras grossir tout seul. Le mien est parti de là.
